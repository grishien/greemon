- 2.9: `-Mock` генерирует всё синтетически (включая CPU/RAM/диск и статику) как функцию номера такта — без случайности и без обращений к железу; два прогона дают идентичные ряды (проверено).

## Фаза 4 (2026-11-15)

- 4.1: альтернативный экран `ESC[?1049h` и `ESC[?25l` пишутся до первого кадра; `finally` цикла пишет `ESC[?25h`/`ESC[?1049l` и зовёт `Restore-GreemonConsole` (режим консоли + кодировка). Проверено на трёх путях выхода: `q`, исключение внутри цикла и остановка конвейера (`Stop-Job` — тот же механизм, что и Ctrl+C для PowerShell). Синтетический `CTRL_C_EVENT` (`AttachConsole`+`GenerateConsoleCtrlEvent`) в тест-окружении не доходит ни до какого процесса — прогон показал, что его игнорирует даже `cmd.exe`; потому доставка именно клавиатурного Ctrl+C не воспроизводилась, а выполнение `finally` при остановке конвейера — документированное поведение PowerShell, проверено Stop-Job.
- 4.2: кадр собирается в `StringBuilder` (`Format-GreemonFrameText` с Pad-параметрами) и пишется одним `Write` после `ESC[H`; очисток экрана/строк (`ESC[2J`, `ESC[J`, `ESC[K`) нет. Чтобы прежний кадр не проступал, каждая строка дополняется пробелами до ширины окна, кадр — пустыми строками до высоты окна (хвост за экраном усекается, завершающего перевода нет — альтернативный экран не прокручивается).
- 4.3: клавиши `q`/`Space`/`r`/`t`/`?`/`1`–`6` + `Esc` (закрывает справку, как `filter_clear` в референсе); состав — автономный набор roadmap, без Tab/Enter/стрелок референса (видов 2–6 с данными нет). Справка «?» — по образцу `action_help`: список клавиш (`_help_line`, состав адаптирован) заменяет строку сообщения, живёт `HELP_SECONDS=15` с, повторное `?`/`Esc`/смена вида закрывают; перенос по `_help_wrapped` (room = max(20, width−2)); при открытой справке высота контента не ужимается (в референсе `height−2−extra`) — строки справляются ниже, на экране 78×23+ помещается. Заморозка: во время заморозки замеры и история не двигаются (в референсе `_show_snapshot`, а с ним и `history.add`, вызывается только когда не заморожено), маркер `[FROZEN]`. Тема по `t`: auto→dark→light→auto (`action_theme_cycle`: terminal→dark→light→terminal). Опрос клавиш вынесен в тонкие функции `Test-GreemonKeyAvailable`/`Read-GreemonKey` (реальный путь — `[Console]::KeyAvailable`/`ReadKey($true)`; подмена нужна только проверочным скриптам).
- 4.4: диапазона `-Interval` в референсе нет (`hwmon.py` — float без клампа, `set_interval` в `monitor.py` — тоже); по решению владельца проекта кламп не вводить (уточнение в чате 2026-11-15). Ноль/отрицательное значение в интерактивном режиме — сообщение в stderr и код 2 (иначе кадр не успевает отрисовываться). Сон — по абсолютному расписанию: следующее плановое время считается от предыдущего планового (`Get-GreemonNextFrameAt`), задержки кадра не накапливаются, отставание пропускается без очереди; короткие `Thread.Sleep` до 25 мс — чтобы клавиши отзывались быстрее интервала.
- 4.5: `-Once` — прежний путь точки входа (два снимка для CPU-дельты, один кадр в текущий поток, без альтернативного экрана и клавиш), код 0.
- 4.6: `[Console]::IsOutputRedirected`/`IsInputRedirected` — сообщение в stderr (RU+EN, с подсказкой `-Once`), код 2. Процессные тесты перенаправляли и stdout тоже, поэтому случай «только ввод перенаправлен при живом терминале» проверен на уровне условия, не отдельным прогоном.
- Наблюдение (не фаза 4): сборка кадра на холодном JIT ~0.3–0.5 с — это материал для замеров и оптимизации в фазе 7.4, здесь не трогали.

## Фаза 5 (2026-11-15)

- 5.1 (уточнение, согласовано с владельцем проекта в чате): roadmap предписывает добавление в пользовательский PATH через `[Environment]::SetEnvironmentVariable(..., 'User')`. Практика на машине разработки: этот API при чтении пользовательского PATH разворачивает `%VAR%`-токены (несуществующая переменная разворачивается в пустоту — запись теряется), а при записи меняет тип значения `REG_EXPAND_SZ` → `REG_SZ` (в PATH пользователя был токен `%OVM_OSCRIPTBIN%`, проверка потеряла его — восстановлено из резервной копии). Решено: гибрид — читаем `HKCU\Environment` без разворачивания; если `%`-токенов в PATH нет — пишем через `SetEnvironmentVariable(..., 'User')`, как требует roadmap; если есть — пишем реестром с сохранением исходного типа значения. Тот же доступ в `uninstall.ps1`.
- 5.1 (следствие гибрида): прямая запись в реестр не рассылает `WM_SETTINGCHANGE`, и freshly запущенные из проводника терминалы не получили бы новый PATH до следующего логина (`SetEnvironmentVariable` рассылает его сам). Установщик/деинсталлятор досылают `WM_SETTINGCHANGE` (`SendMessageTimeout`, lParam `"Environment"`) после изменения PATH; установщик — при каждом успешном запуске (чинит случай «запись в реестре есть, проводник о ней не знает»).
- 5.1 идемпотентность: повторный запуск не дублирует запись (сравнение записей PATH без учёта регистра и завершающего `\`) и обновляет файлы (каталоги `bin\`, `src\` в папке установки сначала удаляются, затем копируются заново — удалённые в исходнике файлы не переживают обновление).
- 5.3: `uninstall.ps1` при отсутствии записи/папки ничего не меняет и не падает; при удалении единственной записи PATH значение удаляется из реестра целиком.
- 5.4 (замер): тест «нового терминала» — реальные новые окна cmd/powershell/wt (`Start-Process`), но окружение процесса-родителя для запуска собирается из реестра (машинный PATH + пользовательский из `HKCU` с разворачиванием, как при логине) — так же его строит проводник после `WM_SETTINGCHANGE`; сам факт доставки `WM_SETTINGCHANGE` проводнику автоматическими средствами не проверялся (требует ручного открытия терминала), вместо него проверено, что содержимое реестра и broadcast корректны. Замечено: `wt.exe` (app execution alias) принимает `-d "путь"` с пробелами только единой строкой аргументов, а завершающий `\` у кавычки (`"-d "C:\""`) ломает разбор — путь для `-d` подаётся без завершающего слэша.
- 5.5: профиль с пробелом и кириллицей смоделирован переопределением `LOCALAPPDATA` на `%TEMP%\...\Профиль Пользователя\AppData\Local` (реальный профиль не переносится): установка, разрешение `greemon` из PATH и запуск с кириллическим путём отработали во всех трёх терминалах; после деинсталляции реестровый PATH побайтово совпал с исходным (включая `%OVM_OSCRIPTBIN%` и тип `REG_EXPAND_SZ`).
