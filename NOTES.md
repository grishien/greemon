## Фаза 2 (2026-11-14)

- 2.1: пути поиска `nvml.dll` взяты из `_Nvml.__init__`: «nvml.dll» через системный поиск и `%ProgramFiles%\NVIDIA Corporation\NVSMI\nvml.dll`. Windows-путь в референсе есть, догадка не нужна; на машине проверки подтверждено: `C:\Windows\System32\nvml.dll` (грузится первым путём), `NVSMI\` в ProgramFiles отсутствует. Загрузка — `LoadLibraryW` до первого вызова; без библиотеки nvml-функции не вызываются (иначе DllNotFoundException на каждом такте).
- 2.2: единицы сверены с `overview.build()`: VRAM — байты, мощность/лимит — Вт (NVML милливаты /1000), PCIe RX/TX — МБ/с (NVML КБ/с /1024), температура °C (датчик 0 = NVML_TEMPERATURE_GPU), загрузка — %. `nvmlDeviceGetMaxPcieLinkWidth` в референсе нет — добавлен по документации NVML (roadmap 2.2 требует максимальную ширину; NVML-имя точное, в `nvidia-smi` это `pcie.link.width.max`).
- 2.2/проверка: на машине NVIDIA GeForce GT 710. Драйвер на неё отвечает NVML rc=3 (NVML_ERROR_NO_PERMISSION) на PowerUsage, EnforcedPowerLimit, PCIe-генерацию/ширину/трафик и UtilizationRates — `nvidia-smi` по тем же полям отвечает `[Not Supported]`. По референсу (`_Nvml._uint`) это `$null` — так и храним, 0 не подставляем. Читаются: имя, VRAM used/total (совпали с nvidia-smi с разницей 0.3 МБ), температура (62 = 62).
- 2.3: запасного пути через `nvidia-smi` в референсе нет — реализован по roadmap: один вызов `--query-gpu=… --format=csv,nounits` за такт (nvidia-smi ищется `Get-Command` один раз при инициализации, обычно в System32). МиБ → байты; `Not Supported`/`N/A`/отрицательные (-1 у nvidia-smi) → `$null`. PCIe RX через nvidia-smi не читается — всегда `$null`.
- 2.4/2.5: `GetSystemTimes` и `GlobalMemoryStatusEx` через P/Invoke, как `_CpuRamFallback`. `Get-Counter`/`Get-CimInstance` в цикле нет (CIM — один запрос при инициализации, п. 2.7).
- 2.6: в референсе диск — дельта `psutil.disk_io_counters()` по всем дискам; аналог — PerformanceCounter `PhysicalDisk(_Total)\Disk Read|Write Bytes/sec` (считает дельту сам, первый снимок отбрасывается). При недоступных счётчиках значения `$null`.
- 2.7: статика один раз при старте: ядра/потоки — один `Get-CimInstance Win32_Processor`; имя GPU, число GPU, VRAM total — из выбранного источника.
- 2.8: `HISTORY=60` (из telemetry.py), серии — набор из `_loop` без LLM-серий `tok_s`/`prefill_tok_s_mean` (они с фазой 6); дробные округляются до 2 знаков, как в `_loop`; недоступное хранится `$null`.
- 2.9: `-Mock` генерирует всё синтетически (включая CPU/RAM/диск и статику) как функцию номера такта — без случайности и без обращений к железу; два прогона дают идентичные ряды (проверено).
- 2.8–2.9 (интеграция): точка входа обёрнута в `if ($MyInvocation.InvocationName -ne '.')` — при точечном подключении доступны реальные функции (проверочные скрипты вызывают их напрямую), при обычном запуске скрипт работает как раньше. Отрисовка и цикл — фазы 3–4.

## Фаза 3 (2026-11-15)

- 3.1: VT включается `GetConsoleMode`/`SetConsoleMode` (флаг `ENABLE_VIRTUAL_TERMINAL_PROCESSING` = 0x0004) на ручке stdout; проверено в настоящей conhost (скрытое окно, Windows 10, Windows PowerShell 5.1): флаг добавляется и корректно снимается при восстановлении. При перенаправленном выводе `GetConsoleMode` не удаётся — функция возвращает `$false`, программа пишет escape-последовательности в поток как есть и не падает. Кодировка вывода — `UTF8Encoding($false)` (UTF-8 без BOM), прежнее значение восстанавливается в `finally` точки входа; в фазе 4 восстановление войдёт в общий `finally` интерактивного цикла.
- 3.2: цвета overview.py truecolor-ом: ACCENT `38;2;52;211;153`, BLUE, AMBER, RED, GREY (он же «dim»); светлая тема меняет только акцент на `#0c8a60` (как `render()`); `solid` — палитра SOLID_* (bright_green/bright_blue/yellow/red/bright_black). `NO_COLOR` (любая непустая переменная, как `os.environ.get(...) is not None` в monitor.py) убирает цвета, но оставляет bold — так же ведёт себя rich с отключенным цветом.
- 3.3: упрощение против `consoleinfo.py`: определение старой консоли по переменным окружения (`WT_SESSION`/`TERM_PROGRAM`/`ConEmuANSI`/`ANSICON`/`TERM`) как в `legacy_console()`, но без переключения шрифта на Cascadia Mono (`switch_font`) и без проверки `cascadia_installed()` — старая консоль всегда получает `solid`. Пути «старая консоль + установлен Cascadia → полное unicode-оформление» нет; запись в `STRATA_GLYPHS` не поддерживается (свой параметр `-Glyphs` есть). Маркер bullet: `●` в unicode, `•` в solid (без проверки шрифта Consolas/Lucida, как в `decide_style`), `*` в ascii.
- 3.5: шапка автономного режима: slot URL показывает `greemon` (в референсном автономном `hwmon.py` там loopback-URL, roadmap требует `greemon`), на месте имени модели — `-Label` (в `hwmon.py` label так же попадает в `engine.model`). Маркер: `LIVE`, → `STALE` при возрасте замера > 6 с (как `render()`), `FROZEN` по флагу заморозки (клавиша — фаза 4).
- 3.7/3.8: модель рендера — порт `build()` на локальных данных; форма совпадает с тем, что кормит в свой fake `/metrics` `hwmon.py` (`live.state=idle`, `engine.model=label`, `requests=[]`, `totals={}`). Скорость в режиме Idle по этому же порту: `run_average_speed` по пустым totals → `$null` → ветка `last request` — плитка Speed показывает `-- tok/s` / `last request`, ровно как референсный автономный hwmon.
- 3.6: вкладки — порт `nav.layout/styled` для шести вкладок; выбранная в квадратных скобках и bold+accent, при нехватке ширины — короткие имена, затем окно вокруг выбранной со стрелками `<` `>`. Виды 2–6 в автономном режиме — заглушка «недоступно в автономном режиме» (текст по формулировке roadmap).
- Макетные допущения (ровно проверить по тексту rich нельзя, уточним визуальным сравнением в фазе 7): плитки в ряду через два пробела (padding (0,1) на cell у `Table.grid`, `4*tile_w+6 ≤ 110` сходится с формулой `tile_w = (min(width,110)-3)//4`); левая колонка полос и таблица запросов — через шесть пробелов (padding (0,3)); колонки таблицы запросов — через два пробела (padding (0,1), `pad_edge=False`). Верхняя граница плитки — как rich Panel с заголовком слева: `╭─ Title ────…─╮`.
- 3.12: ширина контента — как в `monitor.py`: окно минус margin (2, в классической консоли 3 и кап 100), внутри `render()` всё ограничено `min(width, 110)`; шапка и строка состояния растянуты на всю ширину окна (как `pad` в `render()`), остальное — ≤ 110. Минимум 78×23 — условие `_paint` в `monitor.py`; ниже — одна строка «окно слишком маленькое, нужно 78×23» (формулировка roadmap).
- Точка входа после фазы 3: два снимка (CPU % по дельте), один кадр Overview в текущий поток, восстановление консоли и кодировки, exit 0. Альтернативный экран, клавиши, точный цикл и `-Once` как отдельный режим — фаза 4. При перенаправленном выводе (нет консольного размера) кадр рисуется в типовых 112×32.
